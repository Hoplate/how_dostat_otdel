# Как достать отдел · Дима на работе

**Нативная играбельная версия 0.2 на Godot 4.5.2.** Это не HTML, Electron,
WebView и не сайт в отдельном окне. Windows-экспорт — самостоятельный `.exe`
со встроенными ресурсами. Есть также Linux x86_64 и исходный проект.

## Запуск

**Готовая игра:** в последнем успешном запуске GitHub Actions откройте раздел
Artifacts, скачайте `OfficeMischief-windows-x64`, распакуйте архив и запустите
`OfficeMischief.exe`. Установка Godot, Python и Node.js не нужна. Внешний доступ
в интернет во время игры не используется.

**Из репозитория на Windows:** скачайте/клонируйте проект и запустите
`start.cmd`. Если готовой сборки ещё нет, скрипт скачает официальный переносимый
Godot 4.5.2 в `.tools/godot`, импортирует ресурсы и запустит игру. Права
администратора не нужны. Первый запуск требует интернета. Собственный путь
к движку можно передать через `GODOT_BIN`.

**Для разработки:** импортируйте `game/project.godot` в Godot 4.5.2 и нажмите F6/F5.
На Linux: `GODOT_BIN=/path/to/godot bash start.sh`.

## Управление

| Действие | Управление по умолчанию |
|---|---|
| Идти / подойти к предмету и выполнить действие | ЛКМ |
| Отменить путь или незавершённую подготовку, в том числе над HUD | ПКМ |
| Ручное движение относительно камеры; отменяет команду мыши | WASD / стрелки |
| Действие рядом, включая вход/выход из укрытия | E |
| Включить/выключить тихий шаг | Ctrl |
| Невинное лицо | Q |
| Показать интерактивные точки и поля зрения | Tab |
| Приблизить/отдалить; переместить камеру | Колесо; средняя кнопка с перетаскиванием |
| Вернуть камеру к Диме | F |
| Пауза; полный экран | Пробел / Esc; F11 |

Клавиши переназначаются в настройках; занятые назначения отклоняются.
Используются физические клавиши, поэтому русская раскладка не ломает WASD.
У всех основных действий есть управление мышью. Инструмент выбирается
автоматически; маркер и стикеры забираются одним действием, не двумя визитами.

## Что работает

Десять эпизодов с постепенным открытием комнат. Дима, Лена, Марина и Паша,
маршруты коллег, поиск виновника, укрытия и ограничения видимости. Пакость
засчитывается после реакции NPC; реакции могут направить другого сотрудника
к следующему объекту. Срабатывают комбо, невинное лицо с ограничениями,
три замечания, таймер смены, победа и поражение.

Три темпа игры. Пауза при потере фокуса, изменение масштаба и перемещение
камеры, настройки звука. Сохранение незаконченной смены каждые 5 секунд и
при выходе; восстановление начинается на паузе. Сохраняются инвентарь,
подготовленные пакости, очки, подозрение, позиции и распорядки.

## Важные границы этой версии

Это **2.5D**: объёмный офис, но персонажи — отрисованные 2D-спрайты,
развёрнутые к камере, с простой процедурной анимацией. Полноценных скелетных
3D-моделей, лицевой анимации и озвучки нет. Все десять сценариев используют
один расширяющийся офис, а не десять разных карт. Руководитель в поздних
эпизодах действует за кадром — его проверки отображаются таймером.

Подробности изменений относительно концепции: [docs/DESIGN.md](docs/DESIGN.md).

## Проверка и сборка

```bash
godot --headless --path game --editor --import --quit
godot --headless --path game --script res://tests/run.gd -- --self-test --report ./test_results.json
godot --headless --path game --script res://tests/playthrough.gd -- --self-test --report ./playthrough_results.json
bash tools/ci_build.sh /path/to/godot
```

`tests/run.gd` проверяет геометрию проходов всех эпизодов, доступность предметов,
отмену, подготовку и реакцию, инвентарь, укрытия, палево, комбо, способности,
паузу, сохранения, клавиши и завершение смены. `tests/playthrough.gd` выполняет
все десять сценариев на обычной сложности через игровые команды; он не
телепортирует Диму и не отключает обнаружение. Это проверки симуляции,
а не замена ручному тестированию GUI и оценке анимации человеком.

CI импортирует проект, запускает эти проверки, экспортирует Windows/Linux и
публикует архивы и отчёты. Отдельная Windows-задача выполняет проверку запуска
нативного `.exe` в headless-режиме. Для экспорта нужны официальные шаблоны
той же версии 4.5.2. Результаты каждого запуска находятся в артефактах CI;
README не подменяет их заранее обещанным успешным статусом.

## Структура

```text
start.cmd / start.sh     запуск вне папки игры
game/
  project.godot          проект и нативные экспортные профили
  scenes/main.tscn       корневая сцена
  scripts/              игра, навигация, NPC, 3D-офис, HUD и сохранения
  data/campaign.json    задания, реплики и десять сценариев
  assets/characters/    четыре согласованных игровых изображения
  tests/                проверки и автоматическое прохождение
tools/                  переносимый запуск и сборка
docs/                   решения, управление, изображения, лицензия движка
.github/workflows/      проверка и экспорт
```
